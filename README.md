# Маркер

Мобильная PWA для промера с берега: направление заброса, время падения, обороты катушки, отметки дна и журнал. React + TypeScript, TanStack Start, Supabase для дополнительного облачного сохранения. Утверждённой дизайн-системы пока нет; интерфейс предварительный.

[Открыть опубликованное приложение](https://danielsoftwaree.github.io/zabrosy/).

## Запуск

Нужен Node.js 22 и npm:

```bash
npm ci
npm run dev
```

Приложение работает локально без env и аккаунта. Перед dev автоматически собирается шаблон автономного HTML. Для production:

```bash
npm run build
npm run start
```

Маршруты: `/` — промер, `/map` — снимок/камера/дно, `/journal` — журнал и перенос данных, `/account` — облако, `/device` — диагностика, `/help` — памятка.

## Полевой сценарий

1. Создайте рыбалку, укажите или измерьте выборку катушки. При необходимости задайте станцию, ориентир и цель на карте либо координатами.
2. Начните промер: касание воды → дно → подмотка с оборотами и отметками → проверка → сохранение. При скрытии экрана или перезапуске сомнительное время не становится замером.
3. Журнал позволяет исправлять записи, повторять забросы, отмечать избранное и сохранять копии JSON, CSV или автономного HTML. Сектор экспортируется в PNG.
4. Длину выбранной лески и горизонтальную дистанцию до цели читайте раздельно. Глубина появляется только после отдельного ввода; положение этой глубины подтверждается явно.
5. Карта дна показывает собственные точки или отдельно импортированные GeoJSON-глубины. Предполагаемая поверхность включается явно и не заменяет исходные точки.

Карта на Canvas поддерживает перемещение, pinch, колёсико и выбор точки. Доступны GUGiK и Esri World Imagery; снимки требуют интернета и не загружаются в офлайн-кэш. Рельеф тоже использует Canvas: касание выбирает глубину, в 3D движение пальцем вращает схему.

Вместо неподдерживаемого на целевом iPhone WebXR используется «Фото». Сначала выберите своё место и второй берег на снимке — расстояние появится сразу. Для выбора произвольной точки на фото отметьте четыре точки кромки воды на карте, зафиксируйте кадр и сопоставьте те же точки. Внутри участка считается приблизительная дальность по плоскости воды, без полей высоты и углов. Движущийся телефон не отслеживается; новый кадр требует новой привязки. Точность на физическом устройстве ещё не проверена.

Локальные ENC/S-57 (`.000` или ZIP с одним листом) можно открыть прямо в приложении через «Карты глубин Одры». Области глубин и изобаты доступны на снимке и в представлении дна. В комплект не включена официальная карта: скачайте лист по ссылке в приложении и выберите файл. ENC хранится только в памяти вкладки; после её закрытия откройте файл снова. Глубины относятся к отсчёту карты, не автоматически к сегодняшнему уровню воды. Свои GeoJSON-точки можно импортировать и сохранять в журнале.

Все основные экраны доступны офлайн после первой успешной загрузки и установки кэша; статус показывает готовность. На iPhone: Safari → Поделиться → На экран Домой. Для камеры/датчиков и установки нужен HTTPS, кроме разработки на localhost.

Данные в браузере могут быть удалены при очистке сайта. Делайте резервные копии. Автономный HTML содержит приложение и записи, работает в памяти; перед закрытием сохраните новую копию через журнал. Его камера и внешние снимки зависят от политики браузера для локальных файлов.

## Supabase

Всего два публичных значения из `.env.example`: URL проекта и publishable key. [Настройка](supabase/README.md) включает миграцию и серверную авторизацию. `service_role` не попадает в клиент или GitHub Pages. Обмен начинается после нажатия «Синхронизировать»; передаются сохранённые сессии и забросы. Черновик и импортированные карты остаются локальными. Конфликты требуют выбора версии. Без настройки облака весь локальный сценарий доступен.

## Публикация на GitHub Pages

Целевой адрес для репозитория `danielsoftwaree/zabrosy` — `https://danielsoftwaree.github.io/zabrosy/`. Статическую сборку создаёт `npm run build:pages` в `dist-pages/`; она использует префикс `/zabrosy/`. Pages отдаёт только файлы приложения, а облачную авторизацию и данные обслуживает Supabase. Обычные `npm run dev` и `npm run build` продолжают работать с корня `/`.

После создания репозитория задайте в **Settings → Secrets and variables → Actions → Variables** только `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичные значения, встраиваемые в браузерный код; пароль, `service_role` и другие секреты туда не добавляются. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. [Workflow](.github/workflows/pages.yml) проверяет код, собирает `dist-pages/` и публикует его после push в `main` или ручного запуска. Для работоспособного облачного входа предварительно примените SQL-миграцию и настройте серверную функцию и её секреты по [инструкции Supabase](supabase/README.md). Само наличие workflow не означает, что удалённые ресурсы уже созданы.

## Проверки

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

`check`: типы, ESLint, unit-тесты, сборка PWA и автономного HTML. E2E запускаются на production-сборке; если порт 3000 занят dev-сервером, остановите его перед проверкой. Linux может потребовать `npx playwright install --with-deps chromium`.

SQL-проверка после миграции: `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/tests/rls.sql`. Результаты и внешние ограничения — в [статусе разработки](docs/tasks/foundation.md).
