# Аппаратные возможности и проверка на телефоне

Статус: браузерный адаптер и диагностический экран `/device`. Это не подтверждение работы на физическом iPhone. Датчики не являются условием ручного промера.

| Возможность | Использование | Ограничение |
| --- | --- | --- |
| DeviceOrientation | Поворот, наклон, относительный ноль | `alpha` не гарантирует азимут; нужна проверка позы и источника |
| Компас WebKit | Показание `webkitCompassHeading` и точности | Нестандартный API; наличие проверяется, отрицательная accuracy отвергается |
| DeviceMotion | Скорость вращения и ускорение для диагностики | Гироскоп не измеряет обороты ручки катушки; интегрирование ускорения не даёт надёжной дистанции заброса |
| Geolocation | Положение телефона на берегу с точностью | Не положение груза; координаты станции пользователь должен подтвердить |
| Wake Lock | Опциональное удержание экрана в активном промере | Проверить feature detection, visibility и повторное получение на устройстве |
| Вибрация | Необязательная обратная связь | Проверять поддержку; основной сигнал всегда визуальный |

Доступ требует защищённого контекста. На телефоне URL локального компьютера по обычному HTTP не заменяет HTTPS. `requestPermission`, где доступен, вызывается непосредственно из нажатия. Нет автоматического запроса при загрузке.

Адаптер различает отсутствие API, отказ, ошибку и разрешение. Даже при разрешении ждёт реальные данные. Невалидные числа и отсутствующие значения остаются неизвестными. Через 3 секунды без новых событий значения снимаются с экрана. UI обновляется не чаще 10 раз в секунду для каждого датчика. При уходе в фон показания очищаются; при остановке и размонтировании подписки снимаются. Секунды падения не переводятся в глубину.

## Приёмка

- Открыть сборку по HTTPS на настоящем iPhone в Safari и с домашнего экрана, затем на Android.
- Проверить согласие, отказ, повторный вход и API без реальных показаний.
- Проверить поворот через 359°/0°, смену позы и ориентации экрана. Диагностический относительный угол не считать готовым азимутом заброса.
- Свернуть и вернуть приложение: старые показания не должны выглядеть свежими.
- Проверить GPS на улице и отображение точности; отказ не блокирует приложение.
- Для продуктового направления отдельно добавить проверку поддерживаемой позы, круговое сглаживание и фиксацию направления в момент начала промера.
- Результат записывать с моделью телефона и версией ОС; тесты с подставленными событиями не заменяют физическую проверку.

## Фото и карта: приёмка на iPhone

Прежний WebXR-сценарий удалён. Сценарий «Фото» не требует пространственных API: обычная камера или системный выбор фотографии, затем четыре пары точек плоскости воды.

- В Safari и с домашнего экрана проверить разрешение/отказ камеры, открытие JPEG/HEIC через системный picker, фиксацию кадра и освобождение треков при выходе/скрытии.
- Выбрать четыре хорошо различимые точки кромки воды на обоих берегах. Не использовать вершины деревьев, стены выше воды или переместившиеся объекты. Все четыре должны находиться в одном обычном кадре 1×.
- Проверить сохранение привязанного кадра при переходе на карту и возврате; новый кадр/новый участок должны сбрасывать прежние пиксельные опоры.
- Сравнить результат внутри участка с несколькими независимо известными горизонтальными расстояниями; записать модель телефона, состояние воды, дату снимка и ошибки выбора. До такой проверки полевую точность не обещать.
- Проверить увеличение фотографии, перемещение без случайных меток, отмену последней точки и запрет расчёта за границами участка.
- Открыть ZIP/.000 ENC через Files, проверить диапазон области на снимке и те же изобаты в 3D. Отсчёт карты не равен автоматически сегодняшнему уровню воды.
- Проверить Canvas сектора и карты: drag/pinch не выделяет текст, случайный pan не добавляет точку. На коротком экране доступны подтверждение и закрытие панели.

Автоматические браузерные проверки подтверждают эти программные переходы с заданными входами. Физическая работа камеры и точность привязки требуют отдельного испытания на iPhone.
