# Рабочий полевой срез

## Публикация и облачный вход

GitHub Pages получает статическую сборку TanStack Start с базовым путём `/zabrosy/` и отдельными HTML-входами маршрутов. На Pages нет Node-сервера приложения. Вход по имени и общему паролю вызывает `marker-login` в Supabase Edge Functions; функция хранит пароль и ключ вывода профиля на сервере и возвращает сессию Supabase Auth. Сохранённые записи клиент синхронизирует напрямую через PostgREST; PostgreSQL RLS проверяет владельца. Два `VITE_SUPABASE_*` значения в сборке публичны. Общий пароль подходит только для доверенной группы: участник с ним может выбрать любое имя.

Workflow и код миграции подготовлены локально. Их наличие не означает, что GitHub Pages, миграция, секреты или Edge Function уже опубликованы. Удалённую авторизацию, RLS и обмен между устройствами проверяют после развёртывания.

## Локальные данные

Один атомарный документ FieldData версии 1 в IndexedDB. Native API достаточно для нынешнего объёма; Dexie пока не добавлен. Функциональное обновление читает актуальную запись в readwrite-транзакции, поэтому две вкладки не перезаписывают друг друга. BroadcastChannel и возврат фокуса обновляют представление другой вкладки. Ошибки записи видны и не подменяются успехом.

Черновик хранится вместе с записями. После перезагрузки стадия falling становится interrupted; скрытие экрана и выход из промера также прерывают отсчёт. Монотонный performance.now не восстанавливается после перезапуска. Калибровка и станция копируются в заброс. Сектор не объединяет разные станции/нулевые ориентиры.

## Положение и глубина

Cast.target — цель, выбранная пользователем, а не установленное место падения груза. Cast.depthPosition — отдельно подтверждённое положение глубины. В собственную модель дна входят только глубины с depthPosition; время падения и длина лески не создают географическую глубину.

Глубины карт выбираются отдельным набором с источником и вертикальным отсчётом. Виды сверху, по дальности и 3D показывают одни точки. График по дальности не является непрерывным разрезом разных направлений. Вертикальное преувеличение 3D указано явно.

Предполагаемая поверхность включается пользователем после подтверждения одного водного участка и сопоставимого уровня воды. Это IDW-оценка по ближайшим точкам в выпуклой области измерений, с ограничением радиуса соседей и пробелами при недостаточной опоре. У ячейки должны иметь опору центр и все углы; экстраполяции за область точек нет. Берег автоматически не распознаётся, статистическая погрешность не выдумывается. Предпросмотр ограничен 1000 точками, весь импорт сохраняется.

## Синхронизация

После нажатия «Синхронизировать» включается обмен сохранёнными сессиями и забросами при изменениях и возвращении сети/фокуса. До этого данные локальные. Черновик, импортированные карты и исходные старые копии не отправляются.

Подтверждённая revision и sent updatedAt образуют локальную очередь: изменение во время запроса остаётся непереданным. Удаления — tombstones; подтверждение первого сохранения после локального удаления также ставит tombstone. Конфликт версий требует выбора пользователя. Удалённая облачная сессия не стирает активный черновик или непереданные дочерние изменения. Смена аккаунта проверяется в каждой серверной операции через expectedOwnerId.

Это консервативная синхронизация записей, не совместное редактирование текста и не постоянно работающий фоновый процесс. Удалённые записи остаются в базе как tombstones.

## Перенос и сборка

JSON — полный версионный backup. CSV — плоская выгрузка забросов с защитой текстовых ячеек от формул. PNG содержит схему сектора без внешнего снимка.

Автономный HTML собирается отдельной Vite library-сборкой из тех же SurveyPanel, JournalPanel, MapPanel. JS/CSS встроены, сервис-воркер и облако в нём отсутствуют. Данные внутри script[type=application/json] экранируются; HTML-импорт читает только этот блок и не исполняет содержимое файла. Автономная копия работает в памяти и требует повторного экспорта до закрытия.

Старый marker-mobile v2 импортируется с сохранением оригинального JSON. Данные неизвестного происхождения остаются в заметках/исходнике вместо выдуманных измерений. Неизвестный v1 не преобразуется автоматически. GeoJSON Point с глубиной в метрах поддерживается; сырой S-57/S-63 требует отдельного проверенного конвертера и реального файла.

## Карта и камера

GUGiK WMS EPSG:4326, 1200×1200, переключение высокого/стандартного разрешения, атрибуция. Внешние снимки не предзагружаются для офлайна. Координаты можно вводить вручную без снимка. Геометрия отделена в shared/lib/geo.ts.

Камера запускается по нажатию и освобождается при уходе/скрытии экрана, включая позднее разрешение незавершённого запроса. Ориентация задней камеры вычисляется из Euler-углов и совмещается вручную с известным ориентиром. Это относительное наведение, не точный WebXR-дальномер. Нет свежего/пригодного направления — нет автоматической метки. Физический iPhone остаётся отдельной приёмкой.
