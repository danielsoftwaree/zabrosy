# Предметные документы для агентов

Это один проект и один предметный контекст. Перед проектированием модуля, написанием спецификации или задач прочитайте корневой [словарь](../../CONTEXT.md), затем [актуальную архитектуру](../architecture.md) и соответствующий файл в `docs/specs/`. Используйте термины словаря в именах типов, тестов и задач. Новое значение термина сначала уточните в спецификации и затем обновите словарь.

Решения, меняющие модель данных, интерфейсы модулей или эксплуатацию, записываются коротко в `docs/decisions/` по мере появления. Отсутствие такого файла не блокирует работу. Исторические `marker-react-*.md` можно читать ради прежних сценариев и ограничений достоверности, проверяя противоречия с текущими документами.
