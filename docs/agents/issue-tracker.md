# Локальные задачи

До появления удалённого репозитория задачи ведутся в `docs/tasks/`. Спецификации — в `docs/specs/`. Для нового крупного среза создавайте `docs/specs/<slug>.md`; если он разбит на несколько задач, создавайте по одному файлу `docs/tasks/<slug>/<NN>-<task>.md` с названием, статусом, зависимостями, наблюдаемым результатом и проверками. Для маленького среза достаточно одного файла, как `docs/tasks/foundation.md`. Не публикуйте issue во внешний сервис без отдельного запроса.

Когда навык говорит «опубликовать спецификацию» или «создать ticket», запишите файл по этому соглашению и верните его путь. Когда говорит «загрузить ticket», прочитайте переданный файл. Навыки Matt Pocock показывают `.scratch/` как типовой путь; в этом проекте используются постоянные `docs/specs/` и `docs/tasks/`, чтобы история решений оставалась в репозитории. Текущий источник правил — `AGENTS.md`.
