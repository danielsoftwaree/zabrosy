# Текущая архитектура Маркера

**Статус:** рабочий локальный срез реализован; внешняя приёмка Supabase и iPhone остаётся отдельной. Это текущий документ для новых работ. `marker-react-spec.md`, `marker-react-implementation.md`, `marker-react-start.md` сохранены как исторический анализ прототипа. Их запрет backend, выбор отдельной Vite SPA с hash routing и требование повторить визуальный язык больше не действуют. Сценарии измерения и ограничения достоверности из них по-прежнему полезны, если не противоречат этой архитектуре.

## Цель и первый срез

Мобильная PWA на React и TypeScript strict. TanStack Start даёт маршруты и клиентскую оболочку. Для GitHub Pages собирается статический сайт с базовым путём `/zabrosy/`; Node-сервер Start на Pages не работает и для облака не нужен. Вход обслуживает Supabase Edge Function, сохранённые записи клиент читает и пишет напрямую через Supabase PostgREST с Auth и RLS. Основной полевой сценарий работает локально без аккаунта и сети после установки PWA.

## Кодовая карта

```text
src/
  app/                  запуск, провайдеры, стили приложения
  routes/               маршруты и сборка экранов
  modules/
    survey/             промер, калибровка, расчёты, отметки
    journal/            сохранённые записи, цели, импорт и экспорт
    map/                сектор, снимок, обзор наблюдений
    account/            вход и облачное сохранение
  shared/
    ui/                 переоформляемые UI-примитивы
    hooks/              общие законченные React-хуки
    lib/                небольшие независимые функции
    storage/            IndexedDB и очередь синхронизации
    server/             общие схемы входных данных облачных операций
    platform/           датчики, Wake Lock, PWA
tooling/                конфигурации инструментов, если поддерживают такой путь
supabase/migrations/     версионируемая схема и RLS
supabase/functions/      серверная функция входа
.github/workflows/       проверка и публикация Pages
docs/                   спецификации, решения и задачи
```

Каталоги появляются по мере потребности. `shared` не знает о модулях; модуль наружу предоставляет небольшой публичный интерфейс. Предметная логика и модель измерения не зависят от React и от способа сохранения. Не вводим отдельные пакеты, контейнеры зависимостей и универсальные repository-интерфейсы до реального второго применения.

Временное состояние полевого интерфейса ведёт небольшой Zustand store `shared/ui/field-ui.ts`: активный вид, содержимое и раскрытие единственного нижнего drawer. Оно отделено от сохраняемых измерений. `MapPanel` передаёт поверхность и действия точки через render-prop, а `SurveyPanel` размещает их в общей компоновке, сохраняя состояние промера при смене вида. На широких экранах отдельная оболочка показывает приложение в iframe того же origin. Подробности — в [решении о полевом drawer](decisions/2026-09-26-field-drawer.md).

## Данные

Локальная запись — native IndexedDB с атомарным функциональным обновлением одного FieldData-документа. Dexie не понадобился для текущего объёма. Черновик промера локальный. Вход по имени пользователя и общему паролю небольшой доверенной группы вызывает Edge Function; она выдаёт сессию Supabase Auth. После явного включения синхронизации клиент обращается к таблицам PostgreSQL через PostgREST, а RLS ограничивает записи владельцем. Подтверждённые ревизии сохраняются с локальными данными, удаление передаётся явно, конфликтные версии требуют выбора. Подробности — в [решениях рабочего среза](decisions/2026-09-26-field-app.md).

Для браузерной сборки достаточно **двух публичных env**: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Service role key используется только внутри Edge Function при создании профиля. Общий пароль и ключ вывода учётных данных задаются только в секретах Supabase. Если публичные env не заданы, локальное приложение запускается без облачных действий. Локальный Supabase CLI и Docker не являются условием запуска фронтенда.

## Отрисовка и устройство

Сектор использует Canvas с pointer-жестами; снимки и географические отметки отображаются Canvas-движком OpenLayers. View и слои используют EPSG:3857; координаты предметной модели остаются WGS84, расстояния считаются геодезически, а не в метрах проекции. GUGiK WMS и Esri XYZ выбираются из небольшого списка провайдеров с атрибуцией. OpenLayers отвечает за pan/pinch/wheel и viewport; React — за выбранные точки, нижнюю панель и данные промера. Рельеф рисуется отдельным Canvas без картографических тайлов; интерполяция не пересчитывается при вращении схемы.

Ориентация, движение, геолокация и Wake Lock — опциональные адаптеры с разрешениями по действию. Сценарий «Фото» использует фиксированное изображение и четыре пары точек плоскости воды. Чистая гомография в `photo-geometry.ts` не зависит от DOM; `camera.tsx` отвечает за камеру/фото и выбор пикселей. `map-tools.ts` хранит временные опоры, режим замера и общий источник глубин. Обычная камера запрашивает предпочтительно задний объектив; доступен выбор фотографии через системный picker iOS. WebXR удалён из действующего кода. Фото не сохраняется в облако, а его цель возвращается к существующему сохранению на карте. Решение: [привязка фото](decisions/2026-09-27-ios-photo-registration.md).

Локальный ENC разбирается лениво загружаемым S-57-парсером. DEPARE, DEPCNT и SOUNDG остаются разными типами данных. `enc-chart-store.ts` хранит лист в памяти вкладки; текущий выбор набора общий для снимка и схемы дна. Публичный репозиторий не содержит официальных ENC или производных наборов.

## Эксплуатация

PWA должна открываться после первой загрузки без сети и не обновляться посреди промера. Синхронизация возобновляется при следующем открытии приложения; постоянную работу в фоне не обещаем. Начальный запуск требует только установки зависимостей. GitHub Actions собирает статический артефакт `dist-pages/` и публикует его на Pages. Облачный режим отдельно требует проект Supabase, миграцию, секреты и развёртывание Edge Function; локальное наличие кода не подтверждает их удалённое состояние. Тестируем расчёты, переходы, локальное восстановление и браузерные сценарии; физические датчики выносим в ручную приёмку.
