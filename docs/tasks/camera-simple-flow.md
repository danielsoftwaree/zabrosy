# Камера без числовых настроек

Статус: экспериментальный WebXR-сценарий снят. Заменён задачей [снимок, фото и глубины](ios-map-photo-depth.md) после подтверждения, что целевое устройство пользователя — iPhone. Сведения ниже описывают прежнюю реализацию, не текущую функцию.
Основание: [сценарий](../specs/camera-simple-flow.md), [решение](../decisions/2026-09-27-guided-ar.md).

## Разбор отказа · 27 сентября 2026

- GitHub Actions подтверждает успешную публикацию версии `1c3452e4d50c41378fe0aedc24da856eb27833e5`. Это не подтверждает версию в кэше конкретного телефона или работу его AR.
- Модель телефона, браузер и точный шаг отказа пока неизвестны; запрошены у пользователя. Причина его конкретного отказа ещё не установлена.
- Реализация требует WebXR `immersive-ar`; обычная камера iPhone в Safari не заменяет этот API. Нативный ARKit отсутствует.
- Ограничение наклона в `waterPlaneTarget` отсекает лучи ближе 5° к горизонту. При высоте камеры 1,5 м над водой это ограничивает расчёт по берегу примерно 17 м; сценарий забросов на 30–80 м так не закрыт. Снятие ограничения само по себе не подтверждает точность.
- При отсутствии попадания и при отклонённом расчёте по уровню воды интерфейс показывает одну общую инструкцию удерживать прицел. Она не объясняет, какое условие мешает результату.
- До приёмки нужны воспроизведение на целевом устройстве и сравнение с известными расстояниями. Результаты моков ниже относятся только к программным переходам и заданным входным данным.

## Изменения

- Прежний дальномер с полями высоты, допуска и калибровкой наклона заменён пространственным WebXR-сценарием. Неиспользуемые расчёты прежнего варианта удалены.
- Основной путь: открыть AR, навести, дождаться устойчивого результата, сохранить горизонтальную дистанцию с источником и временем.
- «Уточнить по берегу» — дополнительный путь с подтверждением близкой границы воды. Высота земли автоматически не считается уровнем воды.
- При отсутствии необходимых API доступно измерение по снимку и обычная камера для наведения. Метрический результат не восстанавливается из картинки, GPS или наклона без опоры.

## Проверка

- TypeScript, ESLint, 55 unit-тестов и Pages-сборка прошли.
- 30 браузерных сценариев прошли, включая отсутствие пространственных API, отказ XR-разрешения, сохранение прямого замера, отмену и подтверждение границы воды, потерю отслеживания, сброс reference space и освобождение ресурсов.
- Проверены 320×568, 390×844 и настольный iframe: прицел в центре XR-вида, панель не заслоняет его, горизонтального переполнения и ошибок страницы нет. Стартовая подсказка на коротком экране получила достаточно места; остальные действия доступны через прокрутку.
- Lock-файл проверен через `npm ci --dry-run` в чистой временной папке. Добавлены только типы WebXR; новых runtime-зависимостей и env нет.

Физическая точность и работа на конкретном телефоне остаются отдельной проверкой; браузерная имитация XR не подтверждает их. Автоматический режим требует поддержки WebXR устройством и браузером. Нативная iOS-оболочка с ARKit в этом изменении не создавалась; неподдерживаемый браузер предлагает снимок и обычное наведение.
